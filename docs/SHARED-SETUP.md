# 두 사람이 함께 사용하기

1. 전달받은 공유 링크를 두 분의 휴대폰이나 PC에서 엽니다.
2. **타임라인** 또는 **신혼집 자금 계획**에서 칸을 수정합니다.
3. Enter를 누르거나 다른 칸으로 이동하면 자동으로 저장됩니다. 상대방 화면에도 자동 반영됩니다.

이메일·비밀번호·로그인 메일이 필요하지 않습니다. 연결한 브라우저는 공유 링크를 기억합니다.
오른쪽 위 공유 아이콘에서 링크를 복사하거나 JSON 백업을 내려받을 수 있습니다.
공유 링크를 가진 사람은 기록을 읽고 수정할 수 있으므로 두 분만 보관하세요.

## 자동 저장과 연결

상단에 `저장 중`, `모든 변경 저장됨`, `연결되면 자동 저장` 상태가 표시됩니다.
인터넷이 끊겨도 수정은 기기에 남고 연결 복구 후 자동 저장됩니다.
브라우저 데이터를 지우면 아직 서버에 반영되지 않은 수정도 지워질 수 있으므로 저장 상태를 확인하세요.

동시에 서로 다른 항목이나 필드를 수정하면 두 변경을 합칩니다.
같은 필드를 동시에 수정할 때는 저장 중인 기기의 수정 값이 우선합니다.
삭제와 수정이 겹치면 수정 내용을 보존합니다. 중요한 변경 전후에는 백업을 사용할 수 있습니다.

월만 정해진 일정은 월 단위로 유지하고, 예식 전날·당일 일정은 예식일에 따라 조정됩니다.
자금 표에서는 원본의 실제 납부 여부를 임의로 판단하지 않습니다. 금액이 같은 월·항목으로 여러 건 있으면 상세 보기에서 각각 수정합니다.

## 관리자 설치

현재 제공한 프로젝트를 사용할 때는 추가 설정이 필요하지 않습니다.
새 프로젝트에는 순서대로 다음 SQL을 적용합니다.

1. [`setup.sql`](../supabase/setup.sql)
2. [`link-workspace.sql`](../supabase/link-workspace.sql)
3. [`link-notifications.sql`](../supabase/link-notifications.sql)

관리자가 안전한 32바이트 난수 토큰을 생성하고 SHA-256 해시와 초기 계획을 비공개 `owol_private.link_workspaces`에 넣습니다.
공간 생성·목록 조회를 제공하는 공개 API는 없습니다.
GitHub Actions 변수 `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`에 공개 프로젝트 설정을 넣고,
개인 공유 링크는 별도로 전달합니다. 토큰을 저장소나 배포 파일에 넣지 않습니다.

## 저장 및 실시간 알림 구조

직접 테이블 접근은 RLS와 권한으로 차단합니다. 읽기·저장 RPC는 원본 공유 토큰을 검증하며,
저장은 revision 비교로 오래된 전체 데이터가 다른 기기의 수정을 덮어쓰는 것을 막습니다.
클라이언트는 충돌 시 최신 데이터를 읽고 변경한 필드만 합쳐 다시 저장합니다.

DB 변경 트리거는 `owol:<토큰의 SHA-256>` 채널에 내용 없는 변경 신호만 보냅니다.
알림에는 계획·금액·원본 토큰을 포함하지 않습니다. Realtime 서비스가 붙이는 메시지 ID 외 개인 데이터가 없으며,
실제 기록은 알림을 받은 뒤 토큰으로 보호한 RPC에서 다시 확인합니다.
알림 자체는 신뢰하지 않으며, 공개 채널의 메시지를 보내거나 듣는 것으로 계획 접근 권한을 얻을 수 없습니다.
연결 복구와 주기적 확인으로 누락된 알림을 보완합니다.

공식 참고: [Supabase Broadcast](https://supabase.com/docs/guides/realtime/broadcast), [함수 권한](https://supabase.com/docs/guides/database/functions).
