# 두 사람이 함께 사용하는 준비 공간

[오월 플랫폼](https://2080fresh.github.io/wed-plan/)은 로그인 없이 공유 링크로 같은 준비 기록을 사용합니다. GitHub Pages가 화면을 제공하고, Supabase가 공동 기록을 보관합니다. **기기 자동 저장과 공동 공간 저장은 별개입니다.**

## 처음 연결하기

관리자가 마련한 공동 공간 하나를 함께 사용합니다. 개인 공유 링크는 로컬 작업 폴더의 `output/우리의-준비공간-링크.txt`에 별도로 전달되며, 저장소나 배포 소스에는 들어가지 않습니다.

1. 전달받은 공유 링크를 평소 사용할 휴대폰이나 PC 브라우저에서 엽니다. **설정 → 함께 쓰는 준비 공간 → 공유 링크로 연결하기**에 링크 전체를 붙여 넣어도 됩니다.
2. **공동 기록 가져오기**를 선택합니다. 현재 기기의 기록은 JSON 백업으로 내려받고 공동 공간의 기록을 가져옵니다.
3. 아직 공동 공간에서 한 번도 저장하지 않았다면 **이 기기의 기록으로 공동 준비 시작**을 선택할 수도 있습니다. 확인 후 현재 기기의 계획을 공동 공간에 처음 저장합니다. 이 선택은 공동 기록의 버전이 1일 때만 표시됩니다.
4. **다른 기기 연결 링크 복사**로 같은 링크를 상대방에게 직접 전달합니다. 다른 기기에서도 링크를 한 번 열어 연결합니다.

이메일, 비밀번호, 계정 등록이나 메일 발송 설정은 필요하지 않습니다. 연결한 브라우저는 링크를 기억하므로 다음 방문에 다시 입력할 필요가 없습니다.

## 편집하고 함께 저장하기

1. 편집을 시작하기 전에 **최신 공동 기록 가져오기**를 누릅니다. 현재 기기의 내용은 적용 전에 JSON으로 백업됩니다.
2. 일정, 예산, 업체, 준비 노트 등을 수정합니다. 변경 사항은 현재 기기에 자동 저장됩니다.
3. 편집을 마치면 **공동 공간에 저장**을 누릅니다. 저장이 성공한 다음 상대방이 최신 공동 기록을 가져오면 변경 내용을 확인할 수 있습니다.

페이지를 새로 열거나 새로고침한 경우에는 최신 공동 기록을 가져온 뒤 공동 공간에 저장할 수 있습니다. 이전에 수정한 기기 기록이 있다면 가져오기 전에 내려받는 백업에 보관됩니다.

두 기기에서 같은 버전을 가져와 편집하면 먼저 저장한 내용만 반영됩니다. 두 번째 저장은 충돌 안내와 함께 거부됩니다. **내 기록 JSON 백업 → 최신 공동 기록 가져오기 → 필요한 수정 다시 적용 → 공동 공간에 저장** 순서로 정리하세요. 현재는 항목별 자동 병합이나 실시간 동기화를 제공하지 않습니다.

## 링크와 기록 보관

- 공유 링크를 가진 사람은 해당 공간의 기록을 읽고 수정할 수 있습니다. 두 분이 보관하고 필요한 기기에 직접 전달하세요. 기기 수나 사용자 수 제한은 없습니다.
- **이 기기 연결 해제**는 현재 브라우저가 기억한 링크만 지웁니다. 기기의 계획, 공동 기록, 다른 기기의 연결은 그대로 남습니다. 다시 연결하려면 공유 링크를 열면 됩니다.
- JSON·Excel 백업에는 준비 계획만 포함되며 공유 링크는 포함되지 않습니다. 링크 파일은 계획 백업과 별도로 보관하세요.
- 사이트의 공개 주소와 Supabase 공개 키만으로는 공동 기록을 읽을 수 없습니다. 브라우저에는 공개 프로젝트 URL과 Publishable key만 사용합니다.
- 공동 공간에는 사진·파일 대신 계획 JSON을 저장하며 최대 크기는 5 MB입니다. 네트워크 오류나 Supabase 프로젝트 일시 중지 중에는 기기 편집과 백업을 계속 사용할 수 있고, 공동 저장은 연결이 복구된 뒤 진행합니다.

## 관리자 설치와 유지 관리

현재 프로젝트를 사용하는 기기는 Supabase URL이나 키를 입력할 필요가 없습니다. 새 프로젝트로 이전할 때만 다음 설치를 진행합니다.

1. SQL Editor에서 [`supabase/setup.sql`](../supabase/setup.sql)을 실행한 다음 [`supabase/link-workspace.sql`](../supabase/link-workspace.sql)을 실행합니다. 두 파일은 다시 실행해도 기존 계획을 지우지 않습니다. 이후 `setup.sql`을 다시 실행했다면 `link-workspace.sql`도 다시 실행하여 링크 기능의 권한을 복원합니다.
2. 관리자가 안전한 난수 생성기로 32바이트 토큰을 생성하고 64자리 소문자 16진수로 표현합니다. UTF-8 토큰의 SHA-256 해시와 초기 계획을 `owol_private.link_workspaces`에 저장합니다. 공간 생성이나 목록 조회를 허용하는 공개 API는 없습니다.
3. 프로젝트 URL과 Publishable key를 GitHub Actions 변수 `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`에 설정합니다. 로컬 개발에서는 `.env.example`을 `.env.local`로 복사해 같은 공개 설정을 입력합니다. 공유 토큰을 소스 코드나 공개 환경 변수에 넣지 않습니다.
4. 완성한 공유 링크를 두 분에게 별도로 전달합니다. 로그인 공급자, 로그인 복귀 주소, SMTP 설정은 사용하지 않습니다.

링크를 바꿔야 하면 관리자가 새 토큰을 생성하고 해당 공간의 `access_hash`를 갱신합니다. 기존 링크는 무효가 되며 모든 기기에서 새 링크로 다시 연결해야 합니다. 현재 화면에는 링크 재발급 버튼이 없습니다.

기존 계정 기반 공동 공간은 삭제하거나 이전하지 않습니다. 새 링크 공간은 별도의 비공개 테이블을 사용합니다.

## 구현과 검증

`owol_private.link_workspaces`는 RLS를 활성화하고 `anon`·`authenticated`의 직접 조회·수정 권한을 차단합니다. 공개 함수 `owol_link_load`와 `owol_link_save`가 비공개 함수에 요청을 전달하며, 비공개 함수는 전달된 토큰의 해시가 일치하는 공간만 읽고 수정합니다. 원본 토큰은 데이터베이스에 저장하지 않습니다. `owol_private`는 Supabase의 Exposed schemas에 추가하지 않습니다.

저장할 때는 행을 잠그고 클라이언트가 가져온 `revision`을 비교합니다. 일치할 때만 계획을 갱신하고 버전을 1 올리므로 오래된 기록으로 다른 기기의 저장을 덮어쓰지 않습니다.

[`tests/link-sql.mjs`](../tests/link-sql.mjs)는 PostgreSQL 기반 PGlite에서 잘못된 토큰 거부, 직접 테이블 접근 거부, 계획 형식·크기 검사, 같은 버전의 중복 저장 차단, 링크 교체, SQL 재실행 시 기록 보존을 검증합니다. 실제 사용 확인은 두 기기에서 같은 링크를 열고 기록 가져오기·수정·공동 저장을 순서대로 진행하면 됩니다.

공식 참고: [Supabase 함수 권한](https://supabase.com/docs/guides/database/functions), [API 키](https://supabase.com/docs/guides/getting-started/api-keys), [PostgreSQL SHA-256](https://www.postgresql.org/docs/17/functions-binarystring.html).
